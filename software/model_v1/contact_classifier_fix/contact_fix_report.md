## Conclusion

- **Fixes the bug on the actual deployed hand (the relevant question)**: YES -- (a)'s per-finger leave-100%-out held-out accuracy averages **100.0%** across all 4 fingers, vs. the deployed model's 14.2% accuracy at the same position (see (c)). This is genuinely held-out data (the 100% rows were never in that fold's training set) for the SAME 4 physical fingertips this model runs on in production.
- **Does NOT transfer to a completely unseen fingertip**: (a2)'s leave-one-finger-out cross-unit check averages only 25.0% at 100% closure -- if a fingertip is ever physically swapped, this specific fix will likely need fresh self-closure data collected for the new unit before it protects against the same bug there. Not a failure of the fix for its actual purpose, but a real, explicit limitation.
- **No regression on genuine touch detection**: YES -- held-out jig test Contact accuracy changed by +0.41 percentage points (88.4% -> 88.8%).

`active_model.pkl` (the currently deployed model) has NOT been modified. The fix is saved separately at `contact_classifier_fix\active_model_contact_selfclosure_fix.pkl` pending a decision to deploy it (swap `MODEL_PATH` in `live_predictor_test.py`).
